# Ops! 프론트·백엔드 통합 확인

## 1. 현재 구조

- `frontend/index.html`: 화면 구조와 API 호출 로직
- `frontend/theme.css`: Ops! 톤의 플랫한 B2B 운영 화면 스타일
- `backend/serving_app/main.py`: FastAPI 앱 시작점과 프론트 정적 파일 제공
- `backend/serving_app/routers/`: 건강, 데이터, 예측, 감시, 지표, 로그 API
- `backend/serving_app/model_loader.py`: 로컬/MLflow 모델 로딩과 캐시
- `backend/serving_app/monitor.py`: 1,000건 창 기반 성능·PSI 감시
- `backend/serving_app/retrain.py`: 재학습, 배포 게이트, 운영 모델 교체
- `backend/tests/`: API, 감시, PSI, 배포 게이트, MLflow 통합 테스트

## 2. 화면과 API 연결

| 화면 | 사용 API | 화면에서 하는 일 |
|---|---|---|
| 홈 | `GET /health`, `GET /metrics/summary`, `GET /monitoring/status`, `GET /predict/results`, `GET /logs` | 서버·모델 상태, 운영 지표, 감시 창, 분석 이력, 요청 로그 표시 |
| 배치 분석 | `GET /data/uploads`, `POST /predict/batch` | 업로드한 CSV와 기간을 선택해 이상거래 배치 분석 실행 |
| 데이터 | `POST /data/upload`, `GET /data/uploads` | CSV 검증·업로드, 저장된 데이터 목록 표시 |
| 시스템 | `GET /health`, `GET /logs`, `GET /logs/{filename}` | 임계값, 재학습 조건, 배포 게이트, 서버 설정, 로그 확인 |

API와 화면은 같은 FastAPI 서버에서 제공되므로, 별도의 프론트 URL 설정 없이 연결된다.

## 3. 실제 확인 결과

- 자동 테스트: **45개 전체 통과**
- `GET /`, `GET /docs`, `GET /theme.css`: HTTP 200
- `GET /health`, `GET /metrics/summary`, `GET /data/status`, `GET /monitoring/status`: 정상 응답
- 샘플 CSV 업로드: 50건, 카드 2장, 판정 가능 12건, 이력 부족 38건으로 저장
- 브라우저: 홈, 배치 분석, 데이터, 시스템 메뉴 전환 확인

## 4. 연결된 운영 모델

`/Users/songgiyoung/Downloads/models/` 의 실제 학습 산출물을 `backend/serving_app/models/` 에 연결했다.

- `fraud_v1.keras`
- `scaler.pkl`


로딩 검사에서 모델 입력 `(None, 20, 17)`, 스케일러 피처 17개, 판정 임계값 `0.28`을 확인했다. 샘플 CSV로 `POST /predict/batch`를 실제 호출해 12건을 판정했고, 대시보드에 모델 `Loaded`, 처리량, 경보 비율, 분석 이력이 표시되는 것을 확인했다. 현재 샘플은 `이상거래여부` 정답 컬럼이 없으므로 Precision·Recall·F2는 계산하지 않는 것이 정상이다.

## 6. 특히 수정한 안정성 문제

MLflow에서 불러온 운영 모델을 재학습할 때, 서버 로컬에 `scaler.pkl`이 없으면 실패하던 문제를 수정했다. 현재는 메모리에 로드된 스케일러를 임시 후보 번들에 저장한 뒤 MLflow Registry에 함께 등록한다. 이 흐름은 MLflow 통합 테스트로 확인했다.
