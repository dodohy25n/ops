# 시연 영상 발표 대본

`시연영상/ops-시연.mp4`(3분 53초, 무음)를 틀어 놓고 읽는 대본입니다. 영상 시각은 녹화 서버의 요청 기록과 프레임으로 맞췄습니다.
영상 파일은 85MB라 저장소에 올리지 않았으니 발표자에게 따로 전달합니다. 녹화 방법은 [시연 영상 시나리오](시연-영상-시나리오.md), 설계 근거와 예상 질문은 [발표자 가이드](발표자-가이드.md)에 있습니다.

## 읽는 법

- **[시각]** 은 영상 재생 시각입니다. 그 시각에 화면이 바뀌면 다음 문단으로 넘어갑니다.
- **⏸** 표시는 영상을 멈추고 말하기를 권하는 곳입니다. 화면이 대사보다 빨리 지나가는 구간입니다. 멈추지 않으려면 *기울임* 문장을 건너뜁니다.
- 전체 시간: 영상 전 30초 + 영상 3분 53초 + 멈춤 약 1분 + 영상 후 1분 ≈ **6분 30초**. 발표 시간 배분의 시연 6분 구간에 맞추려면 ⏸ 두 곳만 씁니다(2:25, 2:53).

## 영상 틀기 전 (30초)

> 카드 사기 모델은 서버가 멀쩡해도 조용히 틀릴 수 있습니다. 지금부터 2024년 하반기 6개월 거래를 한 달씩 넣으면서, 저희 시스템이 언제 알림만 보내고, 언제 재학습하고, 언제 모델을 바꾸는지 보여 드리겠습니다. 7·8월은 실제 데이터이고, 9월 명절과 10월 이후 신종 사기는 저희가 주입한 시뮬레이션 데이터입니다.

## 영상 중

### 홈 · 시작 상태 (0:00 ~ 0:13)

**[0:00]** 홈 화면
> 운영 대시보드입니다. 서버 상태와 처리 지표가 모두 정상입니다.

**[0:05]** 오른쪽 "현재 모델"로 내려감, 커서가 τ를 가리킴
> 지금 운영 중인 모델은 v1, 판정 기준점 τ는 0.28입니다.

### 시스템 · 감시 규칙 (0:13 ~ 0:27)

**[0:13]** 운영 감시 기준
> 규칙은 세 줄입니다. 판정한 거래를 1,000건씩 묶어 Precision과 Recall을 재고, 기준 아래 창이 두 번 연속 나오면 재학습합니다. 분포 변화를 보는 PSI는 알림만 보냅니다.

**[0:20]** 배포 게이트로 내려감
> 재학습한 후보는 Recall 0.95 이상, 경보 6% 이하, 그리고 지금 모델보다 F2가 낮지 않을 때만 교체됩니다.

### 7월 · 게이트가 후보를 막음 (0:27 ~ 1:21)

**[0:27]** 데이터 탭, 7월 CSV 업로드
> 7월 실제 거래 CSV를 올립니다. 서버가 컬럼과 값을 검사하고, 카드별 직전 거래가 19건 이상인 거래만 판정합니다.

**[0:39]** 시뮬레이션 탭, 기간 7월 1일~31일 지정 후 분석 실행
> 판정 기간을 7월 한 달로 지정해 분석합니다.

**[0:49]** 분석 결과
> 4만 건을 판정했고 Recall은 0.91입니다.

**[0:57]** 빨간 운영 감시 문구
> 그런데 7월 말 34번째 창에서 Recall이 두 창 연속 기준 아래로 떨어져, 재학습이 자동으로 요청됐습니다.

**[1:05]** 홈 › 운영 감시 카드, 34번 창에 "재학습 요청" 표시
> 34번 창이 재학습을 요청한 지점입니다.

**[1:10]** 빨간 이벤트 "후보 v2 게이트 미달 → 기존 모델 유지"
> 후보 v2는 F2가 지금 모델보다 나았지만, Recall 0.923으로 출시 기준 0.95에 못 미쳐 게이트에서 떨어졌습니다. 그래서 v1이 계속 판정합니다.

**[1:17]** 파이프라인 "후보 v2 · 미달 · 유지"
> *이 부분은 뒤에서 팀의 설계 질문으로 다시 말씀드리겠습니다.*

### 8월 · 아무 일도 없음 (1:21 ~ 1:40)

**[1:21]** 8월 분석 실행 → **[1:32]** 결과
> 8월도 실제 데이터입니다. 기준 미달 창이 하나 있었지만 연속이 아니어서 재학습하지 않았습니다. 평소에는 조용한 것이 정상입니다.

### 9월 명절 · PSI는 알림만 (1:40 ~ 2:09)

**[1:40]** 9월 분석 실행
> 9월부터는 시뮬레이션입니다. 명절 주간인 9월 13일부터 19일까지 거래 금액을 1.5배로 키웠습니다.

**[1:52]** 운영 감시 문구 "PSI 주의 1개 · 경고 8개"
> 금액 분포가 바뀌어 PSI 경고가 8개 창에서 울렸습니다. 하지만 성능은 유지돼서, 명절 때문에는 재학습하지 않았습니다.

**[2:00]** 홈 › 이벤트 "후보 v3 게이트 미달"
> 재학습이 한 번 요청되긴 했는데, 명절 직전 실제 거래의 Recall 하락 때문이었습니다. 후보 v3는 Recall과 F2 모두 지금 모델보다 낮아 게이트가 막았습니다.

### 10월 신종 사기 · 재학습 → 교체 (2:09 ~ 2:54) — 하이라이트

**[2:09]** 10월 분석 실행
> 10월부터는 해외·소액·인터넷·새벽 결제 4건 연속이라는, 학습 데이터에 없던 사기를 매달 320건 넣었습니다.

**[2:19]** 홈 › 파이프라인, fine-tuning "재학습 중", 감시 카드 "재학습 진행 중"
> 분석이 끝나자마자 재학습이 시작됐습니다.

**[2:24]** "후보 v4 · 통과 · 교체", 오른쪽 현재 모델 1 → 4, τ 0.28 → 0.16
> 방금 게이트를 통과해서 운영 모델이 v4로 바뀌었습니다.

**⏸ [2:25] 멈춤 권장**
> 서버를 멈추거나 사람이 승인하지 않았습니다. 재학습, 시험, 교체가 몇 초 만에 자동으로 일어났습니다.

**[2:31]** 초록 이벤트 "후보 v4 게이트 통과 → 운영 교체"
> 후보 v4는 같은 시험지에서 Recall 0.953, F2 0.903을 받았습니다. 지금 모델은 0.845, 0.829였습니다. 세 조건을 모두 통과했습니다. *번호가 v4인 이유는 앞서 떨어진 v2, v3도 기록으로 남기 때문입니다.*

**[2:40]** 현재 모델 "CardFraudLSTM 4"
> 현재 모델이 4로 바뀌었고, 새 판정 기준점은 0.16입니다.

**[2:46]** 시뮬레이션 탭, 10월 v1의 결과 "Recall 78.74%"
> 교체 직전 v1의 10월 성적입니다. Precision은 77%로 평소와 같은데 Recall만 0.787로 떨어졌습니다.

**⏸ [2:53] 멈춤 권장**
> 모델이 모르는 사기는 경보 자체가 울리지 않아서 Precision 계산에 들어가지 않습니다. 그래서 Precision만 보면 놓치고, Recall까지 감시해야 합니다.

### 11·12월 · 재시작 없이 v4가 판정 (2:54 ~ 3:40)

**[2:54]** 11월 분석 실행 → **[3:05]** 결과 머리글 "모델 4 · τ 0.16"
> 서버를 재시작하지 않았는데 11월부터 v4가 판정합니다. 분석할 때마다 Registry에서 운영 모델을 확인하기 때문입니다.

**[3:12]** 홈 › 감시 카드 "운영 v4 감시 중"
> 같은 신종 사기가 계속 들어오지만 Recall이 0.964로 돌아왔고, 감시 창도 v4 기준으로 새로 시작했습니다.

**[3:24]** 12월 분석 → **[3:35]** 결과
> 12월도 v4가 Recall 0.958을 유지합니다.

### 분석 이력 (3:40 ~ 3:53)

**[3:40]** 홈 › 분석 이력 6줄
> 6개월 이력입니다. 10월까지는 v1, 11월부터는 v4가 판정했습니다.

## 영상 끝난 뒤 (1분)

> 정리하면 PSI는 알림만, 재학습은 성능이 두 창 연속 떨어질 때만, 교체는 게이트를 통과할 때만 일어났습니다.
>
> 한계도 말씀드리겠습니다. 첫째, 명절과 신종 사기는 시뮬레이션이고, 정답이 판정 직후 바로 들어온다고 가정했습니다. 둘째, 7월처럼 지금 모델보다 나은 후보도 Recall 0.95라는 절대 기준 때문에 떨어질 수 있어, 이 규칙을 완화할지는 남은 과제입니다. 셋째, v4는 Recall 0.953, 경보 5.45%로 기준과의 여유가 작고, 교체 후 다시 나빠질 때 되돌리는 롤백은 아직 구현하지 않았습니다.
