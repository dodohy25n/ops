## 테스트 25개

다음 테스트는 모두 통과했습니다. Registry 통합 테스트는 별도의 임시 DB와 합성 시험용 모델로 실행했습니다.

### 배포 게이트

| 테스트 | 검증한 동작 |
|---|---|
| candidate_equal_to_current_passes | 운영 모델과 같은 성능의 후보는 F2 회귀 없이 통과합니다 |
| current_model_is_required | 비교할 운영 모델 없이 게이트를 호출할 수 없습니다 |
| recall_boundary_and_failure | Recall 경계값에서 통과하고 하한 미달이면 실패합니다 |
| direct_alert_limit_blocks_precision_proxy_loophole | Precision 참고값을 넘더라도 경보가 상한을 넘으면 차단합니다 |
| f2_regression_blocks_otherwise_acceptable_candidate | Recall·경보 조건을 만족해도 현재 모델보다 F2가 낮으면 차단합니다 |
| each_model_uses_its_own_threshold_on_same_labels | 같은 데이터에서 각 모델의 τ를 적용합니다 |
| insufficient_evaluation_is_not_promoted | 전체 표본이나 이상거래 수가 부족하면 승격하지 않습니다 |
| invalid_predictions_fail_closed | NaN·무한대·범위 오류·길이 불일치를 거부합니다 |
| average_precision_groups_tied_scores | 동점 점수의 average precision이 정답 순서에 영향받지 않습니다 |

## 재현

데이터 준비와 스케일러 생성, v1 학습 이후 프로젝트 최상위 폴더에서 실행합니다.

```bash
python -m unittest discover -s backend/tests -t . -v
python -m backend.serving_app.train_and_register
```

등록 명령은 v1을 버전 1로 등록하고 `champion`으로 지정합니다. 이미 운영 모델이 있으면 거부합니다. 테스트 통과는 프로그램의 제어 흐름이 맞다는 결과이며, 실제 v2 fine-tuning과 게이트 교체의 전체 시연은 아직 실행하지 않았습니다.
