# 시연 영상 시나리오

새 화면(홈 · 시뮬레이션 · 데이터 · 시스템) 기준의 녹화용 대본입니다. 2026-10-08에 깨끗한 Registry로 리허설해
7·10월은 화면 조작으로, 나머지 달은 `run_demo.py`로 돌렸고, 숫자가 [시연 실행 로그](results/시연-실행-로그.txt)와 모두 같았습니다.
설계 근거와 예상 질문은 [발표자 가이드](발표자-가이드.md)에 있습니다.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 길이 | 약 5분 30초 (12월을 빼면 5분) |
| 방식 | 화면 녹화 + 내레이션. 재학습이 요청부터 게이트 결과까지 5~6초라 끊지 않고 찍을 수 있습니다 |
| 보여줄 장면 세 개 | ① 7월: 게이트가 후보를 막음 ② 9월: PSI는 알림만 ③ 10월: 신종 사기로 재학습 → 교체 |
| 반드시 말할 것 | 9월 명절과 10~12월 신종 사기는 주입한 시뮬레이션 데이터입니다 (오프닝, 10월에 한 번씩) |

## 2. 촬영 전 준비

### 2-1. 깨끗한 시연 서버 띄우기

기존 `backend/mlflow.db`로 띄우면 이전에 쌓인 후보 버전과 감시 기록 때문에 숫자가 달라지고, 실제 Registry에도 v2~v4가 남습니다.
그래서 빈 폴더를 Registry와 저장소로 쓰는 서버를 따로 띄웁니다. 모두 프로젝트 최상위 폴더에서 실행합니다.

① 빈 폴더 만들기

```bash
rm -rf /tmp/ops-demo && mkdir -p /tmp/ops-demo
```

② 그 폴더의 Registry에 v1을 champion으로 등록하기. 마지막 줄에 `v1 기준 운영 모델 등록: 버전 1, τ 0.28, 별칭 champion`이 나오면 정상입니다.

```bash
MLFLOW_DISABLE_AGENT_HINT=1 FRAUD_API_DIR=/tmp/ops-demo FRAUD_MLFLOW_DIR=/tmp/ops-demo .venv/bin/python -m backend.serving_app.train_and_register
```

③ 서버 띄우기. `LOADING_MODE=eager`를 꼭 붙입니다. 기본값 `lazy`는 첫 분석 전까지 모델 정보를 읽지 않아서 오프닝 화면의 기준값이 전부 `-`로 나옵니다.

```bash
MLFLOW_DISABLE_AGENT_HINT=1 FRAUD_API_DIR=/tmp/ops-demo FRAUD_MLFLOW_DIR=/tmp/ops-demo LOADING_MODE=eager .venv/bin/uvicorn backend.serving_app.main:app --port 8078
```

④ 8~12월 CSV는 미리 올려 둡니다 (다른 터미널에서). 업로드는 같은 화면을 여섯 번 반복할 뿐이라 7월 한 번만 화면에서 보여줍니다.

```bash
for m in 08 09 10 11 12; do curl -s -o /dev/null -F "file=@data/scenarios/2024-$m.csv" http://127.0.0.1:8078/data/upload; done
```

다시 찍어야 하면 ①부터 다시 합니다. 같은 폴더를 재사용하면 감시 창이 이어서 쌓여 숫자가 달라집니다.

### 2-2. 화면 세팅

- 브라우저 창은 **1440×900 이상**으로 둡니다. 더 좁으면 "모델이 업데이트되는 과정"의 8단계가 가로 스크롤로 잘리고 상단 메뉴가 줄바꿈됩니다.
- 브라우저 확대 100%, 북마크바 숨김, 방해 금지 모드를 켭니다.
- 파일 선택 창에서 `data/scenarios` 폴더를 미리 한 번 열어 둡니다. macOS가 마지막 폴더를 기억해서 녹화 중에 폴더를 찾지 않아도 됩니다.
- 터미널은 녹화 화면에 넣지 않습니다. 서버 로그가 계속 올라가서 시선을 뺏습니다.

### 2-3. 녹화 직전 체크리스트

- [ ] 홈 상단 배지 `Server Healthy`, `MODEL_SOURCE=mlflow`
- [ ] 홈 오른쪽 "현재 모델"이 `CardFraudLSTM 1`, τ `0.28`, 운영 모델 (champion)
- [ ] 홈 "재학습 Recall 기준"이 `86.32%`
- [ ] 시스템 › 운영 감시 기준의 연결 상태가 `CSV 분석마다 적용`
- [ ] 시뮬레이션 › 저장된 CSV 목록에 2024-08 ~ 2024-12 다섯 개
- [ ] 홈 "분석 이력"이 비어 있음

## 3. 장면별 대본

날짜 입력은 **매달 꼭 1일~말일로 지정**합니다. 비워 두면 CSV 안의 이력 행(직전 19건용)까지 판정해서 숫자가 로그와 달라집니다.

### 장면 0. 오프닝 (0:00 ~ 0:30) · 홈 맨 위

| 조작 | 가리킬 곳 |
|---|---|
| 홈 화면에서 시작, 천천히 아래로 조금 스크롤 | 서비스 운영 지표, 오른쪽 "현재 모델 CardFraudLSTM 1 · τ 0.28" |

> 카드 사기 모델은 서버가 멀쩡해도 조용히 틀릴 수 있습니다. Ops!는 카드 거래 CSV를 받아 이상거래를 판정하고, 판정 결과로 모델 성능을 감시해 재학습과 교체까지 이어 주는 운영 도구입니다. 지금 운영 중인 모델은 v1, 판정 기준점 τ는 0.28입니다. 2024년 하반기 6개월을 한 달씩 넣어 보겠습니다. 7·8월은 실제 데이터이고, 9월 명절과 10월 이후 신종 사기는 저희가 주입한 시뮬레이션입니다.

### 장면 1. 감시 기준 소개 (0:30 ~ 1:00) · 시스템

| 조작 | 가리킬 곳 |
|---|---|
| 시스템 탭 클릭 | 운영 감시 기준: Recall 트리거 `0.8632 미만 (평균 − 2σ)`, 재학습 조건 `2개 창 연속 미달`, PSI `알림만` |
| | 배포 게이트: Recall 하한 `≥ 0.95`, 경보 비율 상한 `≤ 6.00%`, 성능 회귀 `F2(후보) ≥ F2(운영)` |

> 규칙은 세 줄입니다. 판정한 거래를 1,000건씩 묶어 Precision과 Recall을 재고, 정상 기간의 흔들림보다 크게 떨어진 창이 두 번 연속 나오면 재학습합니다. 데이터 분포 변화를 보는 PSI는 알림만 보냅니다. 재학습한 후보는 Recall 0.95 이상, 경보 6% 이하, 그리고 지금 모델보다 F2가 낮지 않을 때만 운영에 올라갑니다.

### 장면 2. 7월 업로드 (1:00 ~ 1:20) · 데이터

| 조작 | 가리킬 곳 |
|---|---|
| 데이터 탭 → 파일 선택 → `2024-07.csv` → 업로드 | 필수 컬럼 칩, 업로드 후 저장된 CSV 목록 맨 위의 2024-07 (74,430건 · 판정 가능 40,324건) |

> 은행 시스템에서 내려받은 거래 CSV를 그대로 올립니다. 서버가 컬럼과 값을 검사하고, 카드별로 직전 거래가 19건 이상 있어야 판정할 수 있어서 판정 가능 건수를 따로 보여 줍니다.

### 장면 3. 7월 분석 · 게이트가 후보를 막음 (1:20 ~ 2:10) · 시뮬레이션 → 홈

| 조작 | 가리킬 곳 |
|---|---|
| 시뮬레이션 탭 → 2024-07 선택 → 2024-07-01 ~ 2024-07-31 → 분석 실행 | 분석 결과: 판정 `40,324`, 경보 비율 `4.30%`, `Precision 78.64% · Recall 91.04% · F2 0.8826` |
| | 운영 감시 문구: `34번째 창에서 recall이(가) 2개 창 연속 기준 미달 → 재학습을 요청했습니다` |
| 홈 탭 → "운영 감시 · 재학습"까지 스크롤 (5초쯤 기다리면 결과가 뜸) | 34번 창 행의 `재학습 요청` 배지, 빨간 이벤트 `후보 v2 게이트 미달 → 기존 모델 유지`, `실패한 조건: Recall 하한` |
| 위로 조금 스크롤 | 파이프라인 fine-tuning `후보 v2`, 배포 게이트 `미달 · 유지` |

> 주입 없이 실제 7월 데이터만 넣었는데, 7월 말에 Recall이 두 창 연속 기준 아래로 떨어져 재학습이 자동으로 요청됐습니다. 후보 v2는 F2 0.866으로 지금 모델 0.839보다 나았지만, Recall 0.923이 출시 기준 0.95에 못 미쳐 게이트에서 떨어졌습니다. 그래서 v1이 계속 판정합니다.

### 장면 4. 8월 · 평소에는 아무 일도 없음 (2:10 ~ 2:30) · 시뮬레이션

| 조작 | 가리킬 곳 |
|---|---|
| 시뮬레이션 → 2024-08 선택 → 2024-08-01 ~ 2024-08-31 → 분석 실행 | `Recall 95.25%`, 운영 감시 문구 `기준 미달 창 Precision 1개 · Recall 0개 · PSI 주의 0개 · 경고 0개`, 재학습 요청 문구 없음 |

> 평소에는 아무 일도 일어나지 않는 것이 정상입니다. 기준 미달 창이 하나 있었지만 연속이 아니어서 재학습하지 않았습니다.

### 장면 5. 9월 명절 · PSI는 알림만 (2:30 ~ 3:15) · 시뮬레이션 → 홈

| 조작 | 가리킬 곳 |
|---|---|
| 시뮬레이션 → 2024-09 선택 → 2024-09-01 ~ 2024-09-30 → 분석 실행 | 운영 감시 문구 **`PSI 주의 1개 · 경고 8개`**, `Recall 92.75%`, `95번째 창에서 … 재학습을 요청` |
| 홈 → 운영 감시 · 재학습 | 이벤트 `후보 v3 게이트 미달 → 기존 모델 유지`, `실패한 조건: Recall 하한, F2 회귀` |

PSI 경고는 **시뮬레이션 탭의 운영 감시 문구에서 가리킵니다.** 홈의 PSI 안내와 창 표는 마지막 창(9월 말)과 최근 10개 창만 보여 줘서, 명절 주입 기간(9/13~9/19, 창 97~104)의 경고가 보이지 않습니다.

> 9월 13일부터 19일까지 거래 금액을 1.5배로 키웠습니다. 금액 분포가 바뀌어 PSI 경고가 8개 창에서 울렸지만, 성능이 유지돼 명절 때문에는 재학습하지 않았습니다. 재학습 요청이 하나 있었는데, 명절 직전 실제 거래의 Recall 하락 때문입니다. 후보 v3는 Recall과 F2 모두 지금 모델보다 낮아 떨어졌습니다. 게이트가 나쁜 후보를 막은 사례입니다.

### 장면 6. 10월 신종 사기 · 재학습 → 교체 (3:15 ~ 4:30) · 시뮬레이션 → 홈

이 영상의 하이라이트입니다. 분석 실행 직후 **바로 홈으로 넘어가야** "재학습 중" 상태가 찍힙니다(5~6초 뒤 끝남).

| 조작 | 가리킬 곳 |
|---|---|
| 시뮬레이션 → 2024-10 선택 → 2024-10-01 ~ 2024-10-31 → 분석 실행 | `Precision 77.51% · Recall 78.74%`, `120번째 창에서 … 재학습을 요청` |
| **곧바로** 홈 → "모델이 업데이트되는 과정" | 감시 카드 배지 `재학습 진행 중`, fine-tuning `재학습 중` → 몇 초 뒤 `후보 v4`, 배포 게이트 `통과 · 교체` |
| 운영 감시 · 재학습 이벤트 | 초록 이벤트 `후보 v4 게이트 통과 → 운영 교체`, `후보 τ 0.16: Recall 0.9531 · F2 0.9028 · 경보 5.45% / 운영: Recall 0.8446 · F2 0.8285` |
| 오른쪽 "현재 모델" | `CardFraudLSTM 4`, τ `0.16` |

> 10월부터 해외·소액·인터넷·새벽 결제 4건 연속이라는, 학습 데이터에 없던 사기를 매달 320건 넣었습니다. 시뮬레이션 데이터입니다. Precision은 평소대로인데 Recall만 0.787로 떨어집니다. 모델이 모르는 사기는 경보 자체가 울리지 않아 Precision 계산에 들어가지 않기 때문입니다. 그래서 Recall까지 감시합니다.
>
> 120번째 창에서 재학습이 시작됐고, 지금 모델에서 이어서 학습한 후보 v4가 같은 시험지에서 Recall 0.953, F2 0.903을 받았습니다. 지금 모델은 0.845, 0.829였습니다. 세 조건을 모두 통과해 운영 모델이 v4로 바뀌었습니다. 번호가 v2가 아니라 v4인 이유는 앞서 떨어진 v2, v3도 기록으로 남기 때문입니다.

교체 직후 감시 카드 배지는 아직 `운영 v1 감시 중`입니다. 판정 창은 다음 분석이 시작될 때 초기화되는 설계라서 정상이며, 11월 분석 후 `v4`로 바뀝니다. 질문이 나오면 이렇게 답합니다.

### 장면 7. 11월 · 재시작 없이 v4가 판정 (4:30 ~ 5:00) · 시뮬레이션 → 홈

| 조작 | 가리킬 곳 |
|---|---|
| 시뮬레이션 → 2024-11 선택 → 2024-11-01 ~ 2024-11-30 → 분석 실행 | 분석 결과 머리글 `모델 4 · τ 0.16`, `Recall 96.44%` |
| 홈 → 운영 감시 · 재학습 | 배지 `운영 v4 감시 중`, 이벤트 `운영 모델 v1 → v4 교체, 판정 창 초기화` |

> 서버를 재시작하지 않았는데 11월 분석부터 v4가 판정합니다. 서버가 분석할 때마다 운영 모델이 누구인지 Registry에서 확인하기 때문입니다. 같은 신종 사기가 계속 들어오지만 Recall이 0.96 수준으로 돌아왔습니다.

12월(`Recall 95.84%`, 재학습 없음)은 시간이 남을 때만 같은 방식으로 넣습니다.

### 장면 8. 마무리 (5:00 ~ 5:30) · 홈 "분석 이력"

| 조작 | 가리킬 곳 |
|---|---|
| 홈 → "분석 이력"까지 스크롤 | 월별 행의 Recall과 `모델 · τ` 열이 10월 `1 · 0.28`에서 11월 `4 · 0.16`으로 바뀌는 지점 |

> 정리하면 PSI는 알림만, 재학습은 성능이 두 창 연속 떨어질 때만, 교체는 게이트를 통과할 때만 일어났습니다. 한계도 있습니다. 명절과 신종 사기는 시뮬레이션이고 정답이 바로 들어온다고 가정했습니다. 7월처럼 지금 모델보다 나은 후보도 Recall 0.95라는 절대 기준 때문에 떨어질 수 있어, 이 규칙을 완화할지는 남은 과제입니다.

## 4. 녹화 중 문제가 생기면

| 증상 | 원인과 대처 |
|---|---|
| 홈 기준값이 전부 `-` | `LOADING_MODE=eager` 없이 띄웠습니다. 서버를 끄고 2-1의 ③으로 다시 띄웁니다 |
| 숫자가 대본과 다름 | 날짜를 비웠거나 같은 폴더를 재사용했습니다. 2-1의 ①부터 다시 합니다 |
| 10월에 "재학습 중"을 놓침 | 결과는 남으므로 그대로 진행하고, 편집에서 그 구간만 다시 찍어 붙입니다 |

## 5. 편집 팁

- 분석 실행 후 결과가 뜰 때까지 4~5초 걸립니다. 영상에서는 1초로 줄이거나 잘라 냅니다.
- 장면 3·5·6의 숫자 문구에는 확대나 강조 박스를 넣으면 보는 사람이 따라오기 쉽습니다.
